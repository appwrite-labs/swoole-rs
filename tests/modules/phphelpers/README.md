# PHP helper and stdext tests

The common PHP helpers are `crates/phphelpers`; stdext (typed
arrays, methods on arrays/strings/streams and the `swoole_*` stdext functions)
is `crates/phpstdext`, whose `src/stdext.c` keeps the Zend VM, PCRE and JSON
calls whose bodies are private to PHP (its README says why).
`native/phphelpers/host.c` is the module's C remainder (its `contract.md` says why), and
`native/corebase/switches.cc` (generated by
`tools/headers.sh`) the build's configure switches, which Rust reads with
`swoole_rs_corebase::built_with`.

## Loaded PHP checks

- `module.py` (`phphelpers-module`): module INI handlers and information-output
  bailouts, compared across engines.
- `runtime.py` (`phphelpers-runtime`) takes `--engine native=DSO --engine
  selected=DSO`, `--build-manifest` (tools/build_ext.py's) and `--output`:
  stdext copied arrays, native callbacks, autoload and object lifetime
  (`runtime.php`), `bailout.php` children for direct/coroutine return/exception,
  and `vm_bailout.php` children that exit from PCRE/JSON warning handlers and a
  VM destructor inside stdext calls.
- `exit_guard.py` runs in the ZTS variant (`variant.yml`).

The `swoole_stdext` originals and `phphelpers-runtime` run in the merge tier's
`phpt-stdext` job on `--stdext` builds. On Linux PHP 8.2, `mb_ucfirst` is
missing, so one original fails on both engines.

```sh
for t in tests/modules/phphelpers/test_*.py; do python3 -m unittest "$t"; done
```
